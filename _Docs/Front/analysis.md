# Анализ ресурсов

Описания структуры базы нет, поэтому разбирался по самим данным: смотрел внешние ключи, справочники и связи, которые ключами не оформлены, но видны в данных. Такие связи проверял запросами.

Обозначения:
- FK - связь через внешний ключ
- без FK - ключа нет, но связь есть по смыслу, проверял запросом

## 2. Продажа товара

## 4. Работа персонала

**Связанные таблицы:** `securityaccess`, `bm_SecurityObjects`, `bm_BonusHistory`, `bm_ShiftsOperations`, `bm_JournalSessions`, `journal`, `bm_JournalBarnetDocs`.

Сотрудник встречается в трех местах: кассовый журнал (`loginid`), документы (`PersonID`) и права (`bm_PersonnelSecurity.PersonID`). Все три ссылки без ключей. Ключи в этом направлении есть только у бонусов на сотрудника, у прав на объекты и у документов на смену. Сама работа на кассе видна по записям журнала: 301 - вход, 386/387 - начало и конец работы, 101 - продажи.

## 5. Остатки

**Основные таблицы:** `bm_StorageOperations`, `bm_StorageOperationsType` (описаны в разделе 1).
**Связанные таблицы:** `bm_JournalBarnetDocs`, `bm_JournalTypeDocuments`, `product`, `storages`, `bm_ReasonDebit`, `closingcount`, `stockperiod`.

Готовых остатков в базе нет: `stock`, `onhand`, `closingcount`, `storagesonhand` пустые, в `stockperiod` только старые записи 2015 года. Остаток приходится считать по движениям склада - сумма `Count` по товару, она уже со знаком (приход плюс, расход минус). `Rest` не заполнена.
